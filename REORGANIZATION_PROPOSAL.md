# Proposal: One repo, one site — a superb online appendix for *A Model of Enclosures*

**Goal (as stated):** end up with a single repository, published at `open-enclose.github.io`, containing the most current code, able to reproduce every figure in the paper, with elegant/readable/reproducible code — and archive what's superseded.

This document proposes how. It is a plan, not a change: nothing has been modified.

## Part 2 — What to take from each codebase

Both authors have *independently converged on the same target design*, and neither has finished it. Matt's cell 91 (the newest cell, with 4 helper functions) and your `generate_trajectories_figure.py` (written today) are the same refactor, done twice.

### Take from Matt's notebook

1. **The 81 markdown derivation cells.** This is the appendix's actual intellectual product — a step-by-step algebraic narrative from first-best → conditional optimum → Nash → global games → monopoly → μ → τ. Nothing in `enclosure_book` matches it. It is the single most valuable asset in either repo.
2. **The sympy derivation blocks.** Real derivations (`diff` the objective, `solve` the FOC at corners, and — nicely — compare *endpoint values* for the convex branch), not equation rendering.
3. **`safe_log_power()`** — the genuinely clever bit. Every locus has the form `l̄ = [expr]^{1/α}` where `expr` changes sign as θ crosses 1 or 1/α. This NaN-masks instead of hand-slicing the θ grid into pieces, so one grid carries every curve.
4. **The visual grammar**, consistent across seven independently-written cells: black/blue = planner, red = decentralized, green = monopoly; dashed = selection criterion; unit-free axes; dotted verticals at θ=1 and θ_H; rotated in-region text.
5. **The hatching technique** (`color='none', linewidth=0, edgecolor=…`, plus an `MplPolygon` fallback for regions `fill_between` can't reach) — non-obvious, hard-won, and what makes the over/under-enclosure wedges legible in grayscale print.

### Take from your `enclose.py`

1. **`Lambda(th, alp, mu)` as the single algebraic pivot.** Every equilibrium object is a function of Λ. This is the correct factoring of the economics; it should survive verbatim.
2. **The clean pure-computation layer** (lines 32–253: 22 functions, zero matplotlib). This is the boundary Matt's notebook completely lacks.
3. **The `ax=None` composability pattern** — lets one function serve both an `interact` slider and a subplot in a multi-panel figure. This is what makes the paper's three-panel figures possible.
4. **LaTeX docstrings carrying the paper's actual equations**, with a documented pdoc build path. Paper-to-code traceability is rare; keep it.
5. **Keyword-with-defaults signatures matched to `ipywidgets.interact`** — the interactive exploration Matt's TODO asks for is already latent here.

### Take from today's `generate_trajectories_figure.py`

The **locus layer design**: named, single-purpose, docstringed, **tagged with paper equation numbers**, τ-aware, returning log units, with `sanity_checks()` assertions. This is what `allpart` should have been.

### Fix in the merge (real defects, not stylistic)

- **`ltbar` vs `tlbar`** — `req()` takes L̄/T̄, `weq()` takes T̄/L̄; `plotreq` has one parameter named `tlbar` and passes it positionally to **both**. One is inverted whenever `tlbar ≠ 1`, and `enclosure_model.ipynb` calls it with `tlbar=0.16`. **This is a live correctness bug on a paper-figure path** — highest priority.
- **`tepvt_g` silently drops its own `mu`** (hardcodes `mu=0` internally).
- **`plotmpts`/`plotmpts2`** carry `TODO: not yet working for mu != 0` and mix μ values within one figure.
- **Matt's cosmetic fudge factors** (`ln_pm - .03`, `ln_ps1 - .017`) nudge analytically-coincident loci apart so both are visible — legitimate, but should be an explicit `label_offset=` parameter, not a buried literal.
- **Matt's triple transcription**: sympy result → hand-rewritten markdown → hand-retyped numpy float. Three chances to diverge, no check. `lambdify` closes this.

## Part 3 — Proposed architecture

A small installable package plus a MyST site, in `open-enclose.github.io`:

```
open-enclose.github.io/
├── myst.yml                    # site config (already exists, extend nav)
├── pyproject.toml              # installable: pip install -e .
├── README.md                   # landing page
│
├── enclose/                    # THE PACKAGE (descended from enclose.py)
│   ├── __init__.py             # curated public API; no `import *` foot-guns
│   ├── model.py                # pure economics. no matplotlib. Λ, le, req, weq, z, zprime
│   ├── loci.py                 # boundary loci: named, eq-numbered, μ- and τ-aware
│   ├── equilibrium.py          # solve(θ,α,c,l̄,μ,τ) -> Equilibrium dataclass
│   ├── symbolic.py             # sympy derivations + lambdify (the missing link)
│   ├── style.py                # the visual grammar: safe_log_power, style_axes,
│   │                           #   common_labels, fill_between_sorted, color/linestyle semantics
│   └── figures.py              # one function per paper figure -> returns fig
│
├── scripts/
│   └── make_figures.py         # regenerates ALL paper figures in one command
│
├── tests/
│   └── test_against_symbolic.py  # lambdify(sympy) ≡ numpy layer, for every locus
│
├── content/                    # the site's narrative pages (MyST markdown + notebooks)
│   ├── 01-model.md             # ← Matt's 81 derivation cells, reorganized
│   ├── 02-figures.ipynb        # reproduce every paper figure, each ~3 lines
│   ├── 03-explore.ipynb        # ipywidgets parameter exploration
│   └── 04-derivations.md       # ← enclosure_book/docs/online_appendix.md (1219 lines)
│
└── archive/                    # superseded, clearly quarantined (see Phase 5)
```

**Three principles behind this layout:**

1. **Computation never imports matplotlib; plotting never does economics.** Your `enclose.py` already honors this for its first 253 lines — extend it to everything. The test is: *can I tabulate the wage gap without drawing a figure?* Today, no (it exists only as a matplotlib coordinate inside `plotmpts`).

2. **The symbolic layer is the source of truth.** Derive in sympy → `lambdify` → the numeric layer is *checked against it in tests*. This kills the triple-transcription problem, and it's how you get "reproducible" in the strong sense — right now every formula in `enclose.py` is an unverified hand-transcription with no test suite.

3. **One function per paper figure.** `figures.py` should read like the paper's figure list. `make_figures.py` regenerates all of them; CI runs it and fails if anything drifts.

## Part 4 — Proposed site structure

The current site has two nav items (Home, Model Construction) pointing at one 1MB notebook. Proposed:

| Page | Content | Source |
|---|---|---|
| **Home** | What the paper is, links to PDF/arXiv/journal, the 2×2 figure, how to run the code | existing README, expanded |
| **The Model** | The derivation narrative: first-best → constrained → Nash → global games → monopoly → μ → τ. Prose + LaTeX, with folded code cells producing figures inline | Matt's 81 markdown cells, reorganized into sections |
| **Reproducing the Paper's Figures** | Each of the 8 figures, each with a 2–3 line call and the paper's figure number/caption | new, thin — the point is that it's *thin* |
| **Mathematical Appendix** | Full derivations, proofs, computational verification | `enclosure_book/docs/online_appendix.md` (1219 lines, already written, satisfies Matt's open TODO "Add online math appendix") |
| **Explore the Model** | ipywidgets sliders over θ, α, c, l̄, μ, τ, running live in the browser | `enclose.py`'s `interact`-ready signatures + JupyterLite (see below) |
| **Code API** | Auto-generated module docs | pdoc, as today |

MyST supports `hide-input` cell tags (already on Matt's TODO), so code folds away and the derivation reads as prose.

### Decision: interactivity via JupyterLite / Pyodide (Python in the browser)

**Decided 2026-07-27.** Sliders cannot run on a static site without either a remote kernel
(Thebe/Binder) or in-browser Python. We're going with **JupyterLite/Pyodide**: no server, no
Binder cold-start, works on plain GitHub Pages, and the model is closed-form numpy so it
evaluates instantly. numpy, matplotlib and sympy are all in the Pyodide distribution, so the
symbolic layer can run live too.

**This makes import hygiene load-bearing in Phase 1, not cosmetic.** `enclose.py` currently
imports `ipywidgets` and `IPython.display` at module level, and none of them are used by live
code — under Pyodide that bloats first load or breaks it. The rule for the new package: the
computation layer imports **numpy only**; matplotlib belongs to the plotting layer;
`ipywidgets` is imported by notebooks, never by the model.

**Rejected alternative:** reimplementing the loci in JavaScript for instant sliders. Faster to
load, but it creates a *second implementation of the same math* — exactly the fragmentation
this whole reorganization exists to remove.

**To verify at Phase 4 (not blocking earlier work):** first-load size (Pyodide + numpy +
matplotlib, cached afterward); the `ipywidgets`↔JupyterLite version pairing, historically
finicky — pin and smoke-test early; and whether the manufacturing extension's
`scipy.optimize.fsolve` justifies pulling scipy into the browser or should ship pre-rendered.

## Part 5 — Phased plan

Ordered by risk: the things that could affect the *paper* come first; cosmetics last.

### Phase 0 — Resolve the figure discrepancy (blocker, do first)
Determine whether the 2024 paper figures differ from the 2026 appendix figures **cosmetically or substantively**. Method: regenerate from Matt's notebook, diff against `paper/Figures/` visually and numerically, and check whether any *locus* moved vs. just fonts/offsets.
- If cosmetic → pick the newer, update the paper's `Figures/` in the RESTUD revision.
- If substantive → this is a correction the revision must carry, and it's urgent.

Also fix the `ltbar`/`tlbar` inversion here and check whether any paper figure was drawn through the affected path with `tlbar ≠ 1`.

### Phase 1 — Build the package, prove it reproduces the paper
Port `enclose.py` → `enclose/` with the layering above; add τ throughout (τ enters only at the `req`/locus layer — it does **not** touch `Lambda`, `le`, or the technology, so it's a much smaller change than `enclose2.py`'s comment implied); fold in Matt's `safe_log_power` + style helpers; write `figures.py` + `make_figures.py`.
**Definition of done: one command regenerates all 8 paper figures**, and they match the canonical set from Phase 0.

### Phase 2 — Symbolic layer + tests
Port Matt's sympy blocks into `symbolic.py`, `lambdify` them, and assert the numeric layer agrees for every locus. Extend the sympy coverage to μ and τ (currently μ's algebra is done *by hand in markdown only* — ~45 cells with no symbolic verification).

### Phase 3 — Port the narrative
Matt's markdown derivations → `content/01-model.md`, restructured into sections, with the inline copy-pasted plotting replaced by `figures.py` calls. Fold in `online_appendix.md` as the math appendix. This is where the site becomes *readable*.

### Phase 4 — Site polish
Nav, `hide-input` tags, interactive page, Code API, cross-links to paper sections.

### Phase 5 — Consolidate and archive
- Move anything still wanted from `enclosure_book` into the new repo.
- `enclosure_book` → README archive notice pointing to `open-enclose.github.io`; optionally GitHub's "Archive repository" setting (makes it read-only, keeps URLs alive).
- Within the new repo, an `archive/` directory for superseded material that's worth keeping but shouldn't confuse: the original `Model_Construction.ipynb`, old `enclose.py`, the 2024 figures. Clearly labeled, excluded from the site nav.
- Delete outright: `enclose2.py` (byte-identical no-op copy), `enclosure_model2.ipynb` (byte-identical duplicate), the ~10 dead functions with zero call sites, the `countour.ipynb` matplotlib-demo scratch file.

## Part 6 — Sequencing against the RESTUD revision

The revision is in flight and the editor's required changes include **a new figure** (`trajectories.png`, item iii). Two options:

- **(a) Revision first, merge after.** Lower risk to the paper; the merge inherits a stable figure set. Do Phase 0 now (it's a possible paper correction), defer Phases 1–5.
- **(b) Merge Phases 0–1 now, then produce the revision's new figure *from the merged package*.** More work up front, but the new figure lands in the reproducible pipeline instead of becoming a fourth parallel implementation — which is exactly how this fragmentation happened in the first place.

**Recommendation: (b), scoped tightly.** Phase 0 must happen now regardless. Phase 1 is worth doing now specifically because `trajectories.png` is currently a *330-line standalone script that reimplements the locus layer* — the third independent copy of the same math. Folding it in now prevents the problem from growing while you're actively editing the paper.
